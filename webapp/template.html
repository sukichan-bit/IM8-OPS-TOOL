Task A

Production Requirement Report

Works out how much of each SKU you still need to produce.

How this works

Compares requested quantity per SKU/warehouse against on-hand (+ on-order, if provided) inventory. To produce = MAX(Requested − On-hand − On-order, 0). Rows needing production are highlighted red; rows with To produce = 0 are green. Warehouse sections appear in a fixed order (OPS-WH01, OPS-WH02, OPS-WH03, USOPS-WH04, USOPS-WH05); rows within each are sorted A–Z by Item number.

Required files
Requested inventory
Requested qty per SKU for dispatched orders (Item number, Warehouse, Requested qty)
D365 on-hand export
Item number, Warehouse, batch rows, Available physical
Optional files (2)
On-order qty
Incoming/in-production qty per SKU — added to on-hand so it isn't double-counted as a shortfall
Item master Saved in this browser
Backfills Product name for SKUs with zero rows in the on-hand export (these get flagged "Verify item master"). Uploaded once, reused automatically on every future run — not shared with teammates or any server.
Output
Add the required files, then run.
→Production requirement report (.xlsx), one sheet per warehouse
→Count of SKUs needing production
→SKUs missing from the item master, flagged
Task B

Fulfillment Check Report

Tells you which open orders actually shipped, and builds the D365 import for the ones that did.

How this works

Joins open sales-order lines to warehouse fulfillment/shipped report(s). Per order: Shipped / Partially Shipped / Not Fulfilled. For fully-shipped orders, also generates the D365 fulfillment import template (one row per unit, batch numbers from the on-hand export).

Required files
D365 open sales order list
Sales order number, Shopify reference, Item/SKU, Warehouse, Ordered qty
Warehouse fulfillment report(s)
One file per warehouse if reports come separately (e.g. a different WMS/3PL per warehouse) — or a single combined file
Optional files (1)
D365 on-hand export
Only needed to fill batch numbers on the import template
Output
Add the required files, then run.
→Fulfillment check report (.xlsx) with a status per order
→D365 fulfillment import template for shipped orders
→Orders in D365 with no matching warehouse record, flagged
Task C

Refund & Cancel Dispatch Check

Confirms whether refunded or cancelled orders shipped, and puts stock back where they didn't.

How this works

For orders flagged "Ops - refund order" / "Ops - to manually fulfil and adjust inventory": confirms whether each actually dispatched, then builds the D365 fulfillment templates and (for never-dispatched orders) the inventory adjustment journal to add stock back on-hand.

Required files
Open SO workbook
Used for refund-date lookups: the "Refunded on" tab and the Actions/Action tab's embedded pivots
Refund / cancel export
The pre-filtered D365 export of lines in scope (Shopify reference, Sales order, Item number, Product name, Quantity, Warehouse, Ship date, Status)
Warehouse fulfillment reports
One file per warehouse if formats differ (e.g. Stord order-level vs. Chinese WMS wide-block) — same as Task B
D365 on-hand export
For batch-number lookup (first batch with Available physical > 0 per Item+Warehouse)
Optional files (2)
Inventory aging report
Adds cost price and unit — needed for the adjustment journal. Matched by Item + Warehouse; without it, cost/unit are left blank and flagged.
Bundle-SKU cost mapping
Only for bundle SKUs with $0 cost in the aging report. JSON: {"BUNDLE-SKU": [{"sku":"COMPONENT-SKU","qty":1}, ...]} — paste each session, nothing is saved between sessions.
Output
Add the required files, then run.
→D365 fulfillment template for dispatched lines
→D365 fulfillment template for lines that never dispatched
→Order lines for the never-dispatched orders
→Inventory adjustment lines putting that stock back on-hand
Task D

D365 Disposal Journal

Turns a damage or defective report into a ready-to-import disposal journal.

How this works

Generates a D365 disposal-journal import file from a damage/defective report: negative-only lines, batch numbers allocated from an on-hand snapshot (largest-first split, flagged UNALLOCATED if stock is insufficient), cost priced from an inventory aging report with a live Cost amount formula. Reconciliation-journal support (stocktake vs. system on-hand) is not yet implemented.

Required files
Damage / defective report
One row per SKU. Works with either a single Quantity column or the older one-column-per-date-range layout — auto-detected, with sample values shown so you can pick correctly if headers are unusual. Warehouse is read from the filename.
Optional files (2)
D365 on-hand export
For batch allocation — without it every line is flagged and Batch number is left blank
Inventory aging report
Adds cost price and unit, matched by Item + Warehouse — without it, Cost price is left at 0 and flagged
Output
Add the required files, then run.
→D365 disposal journal (.xlsx), negative lines only
→Batch allocation per line, largest batch first
→Lines that stock couldn't cover, flagged UNALLOCATED

Task F

Amazon Sales Order Lines

Converts one month of Amazon transactions into D365 sales order lines.

How this works

Converts an Amazon Transactions Details export into D365 SO lines for one month, following the same tie-out process each time: order lines from the "SKU + Refund" tab's Order block (SKU remap applied, item master used for Product name/Unit), plus one SER line per mapped Summary column (Duty & Tax skipped, the "Sum of other" column computed as Grand Total minus Transfer, refund counted once). The total must match the Summary tab's Net sales figure to the cent before downloading.

Required files
Amazon transactions details
The monthly export, with "Summary" and "SKU + Refund" tabs
Output
Add the required file, then run.
→D365 sales order lines (.xlsx), reconciled to the cent against Net sales
→Amazon SKUs with no item master mapping, flagged
Task G

B2B Freight Cost Calculator

Enter a destination and ordered quantities, then estimate shipping cost from one warehouse — or compare all of them.

How this works

Shipment weight is estimated from the ordered quantities below (actual weight vs. estimated volumetric weight — greater of the two wins), unless you enter real outer-carton dimensions/gross weight once packed, which override the estimate. The destination country and ZIP/postal code resolve a rate card's zone automatically where possible (Stord's US domestic cards use the real USPS zone chart, by ZIP) — a manual override is always available and is clearly labelled when used, never silently assumed. A shipment heavier than a rate card's own maximum is proposed as a split into multiple consignments where the card allows it; otherwise it's marked "Quote required" rather than guessed at. Rate cards and the product catalogue are your own data — maintained below and saved in this browser.

Output
